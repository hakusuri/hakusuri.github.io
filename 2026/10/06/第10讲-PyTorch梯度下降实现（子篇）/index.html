10.7.1 PyTorch 自动求导机制

10.7.1.1 什么是自动求导

  • Torch.autograd 包为张量上所有操作提供了自动求导机制。
  • PyTorch 中有两种求梯度的方法：
    1. torch.autograd.backward()
    2. torch.autograd.grad()
  • 在计算梯度之前，需要首先明确哪个变量需要计算梯度，在张量创建时，将需要计算梯度的张量的 requires_grad 参数设置为 True。
  • 为方便理解，把自己定义的变量称之为叶子节点（leaf nodes），而基于叶子节点得到的中间或最终变量则可称之为结果节点。

10.7.1.2 Tensor 中通常记录的属性（照录）

属性 课件说明
data 即存储的数据信息
requires_grad 设置为 True 则表示该 Tensor 需要求导
grad 该 Tensor 的梯度值；如果利用 torch.autograd.backward() 方法求梯度时，tensor 的梯度会自动累加
grad_fn 叶子节点通常为 None，只有结果节点的 grad_fn 才有效，用于指示梯度函数是哪种类型
is_leaf 用来指示该 Tensor 是否是叶子节点

一句话记忆：只有叶子节点（is_leaf=True 且 requires_grad=True）才会有非空的 .grad 可读，中间变量的梯度默认算完即丢。

10.7.1.4 torch.autograd.grad()（参数表照录）

注：课件上写的是 torch.autograd.grad(outputs，inputs)，后面几个参数（grad_tensors=None, retain_graph=None, create_graph=False, only_inputs=True, allow_unused=False)）来自课件参数表，本文按官方签名排列。

与 backward() 的关键差别（照录 + 强调）：

  • torch.autograd.grad(outputs，inputs) 计算梯度，需要传入参数，返回参数梯度值列表；
  • backward() 则是没有返回值，梯度写进 .grad 里。

参数作用（课件照录）：

参数 课件说明
outputs 结果节点，即被求导数
inputs 叶子节点
grad_outputs 类似于 backward 方法中的 grad_tensors
retain_graph 同上（重复调用 backward 需要设为 True）
create_graph 同上（设为 True 可算高阶梯度）
only_inputs 默认为 True，如果为 True，则只会返回指定 input 的梯度值；若为 False，则会计算所有叶子节点的梯度，并且将计算得到的梯度累加到各自的 .grad 属性上去
allow_unused 默认为 False，即必须要指定 input，如果没有指定的话则报错

10.7.1.6 易错点

  1. requires_grad 必须在创建时给对：x = torch.tensor(2.) 之后 x.requires_grad 默认是 False，此时 z.backward() 会报 element 0 of tensors does not require grad。要么创建时写 requires_grad=True，要么事后调用 x.requires_grad_()（带下划线表示原地修改）。
  2. 只有叶子节点的 .grad 才留得住：对中间结果（结果节点）print(y.grad) 得到的是 None；若确实要，用 y.retain_grad()。
  3. grad 会累加，不清零必出错：backward() 是累加而不是覆盖，循环里不清零，梯度会越来越大。课件原话：「grad 会自动累加梯度，在每轮计算梯度前，要将梯度清 0」。
  4. backward() 与 grad() 返回值不同：backward() 返回 None（直接读 .grad），grad() 返回梯度列表/tuple（参数在 inputs 里指定，且默认不给叶子节点写 .grad）。
  5. 计算图默认用完即销毁：想对同一张图重复求导，要 retain_graph=True；想求二阶导，要 create_graph=True。
  6. .data 与 .detach()：读数值用 .item()（标量）或 .data.numpy()；手写参数更新时课件写成 w.data = w.data - ...，用 .data 是为了绕过 autograd 的记录，属于”老写法”，新版本更推荐 with torch.no_grad():。

10.7.2.5 易错点

  1. torch.randn(1, ...) 得到的是形状 (1,) 的张量，不是标量。取值一律用 .item()；写成 torch.randn(()) 或 torch.tensor(np.random.randn()) 可得到 0 维张量，但打印与广播行为会略有差别。
  2. 只有浮点张量能求导：torch.tensor([1,2], requires_grad=True) 会直接报错（整型不能求导）。
  3. numpy 数组与 torch 张量混算：w * x 里 x 是 float64 的 numpy 数组、w 是 float32 张量，结果会被提升成 float64。想避免就把数据也转成张量：x = torch.tensor(x, dtype=torch.float32)。
  4. 梯度累加：如果没有 optimizer.zero_grad()（或 w.grad.data.zero_()），下一轮 backward() 会把这一轮的梯度加上去，表现为 Loss 先降后飞。
  5. 求导前必须已经调用过 backward()：第一轮就写 w.grad.data.zero_() 会报 AttributeError: 'NoneType' object has no attribute 'data'，因为此刻 w.grad 还是 None。
  6. 优化器建在循环内只对无状态优化器安全：torch.optim.SGD（无 momentum）每轮重建等价；SGD(momentum=0.9)、Adam 这类带状态的优化器会丢掉动量/二阶矩，必须建在循环外。
  7. 打印别忘 .item()：直接把张量塞进 "{:.4f}".format(...) 在部分版本会报警告或格式错误，统一用 .item() 最稳。

10.7.3 PyTorch 实现梯度下降法（多元线性回归）

10.7.3.1 题目描述（照录）

本实例根据梯度下降法的基本原理，完成借助 PyTorch 的自动求导机制实现梯度下降法求解多元线性回归问题。

相关知识点详见 10.1：梯度下降法基本原理，TensorFlow 实现代码详见 10.4 实例：TensorFlow 实现梯度下降法；PyTorch 自动求导机制详见 10.7.1。

10.7.3.2 核心概念：多元回归为什么要”补一列 1 + 用矩阵乘”

一元线性回归是 y = w·x + b，两个参数 w、b 是两个标量；
多元线性回归要把 m 个特征一起用上，写成矩阵形式最省事：

$$\hat{Y} = XW$$

其中：

  • X 的形状是 (n, 3)：第 0 列固定为全 1（增广列，吸收偏置 b），第 1 列是归一化后的面积，第 2 列是归一化后的房间数；
  • W 的形状是 (3, 1)：第 0 个分量就是偏置 b；
  • Y 的形状是 (n, 1)。

把偏置塞进权重向量，是第 9 讲的重点，这里再用一次：这样只需要维护一个待求导参数 W，求导与更新都变成一次操作。

10.7.3.5 易错点

  1. 学习率必须跟着数据尺度走：一元回归用原始面积（几十~一百多）时学习率只能取 0.00001；本节把面积/房间数都归一化到 [0,1] 后才敢取 0.2。不归一化 + 大学习率 = 直接发散（Loss 变 nan）。
  2. np.stack 的 axis=1 不能写成 axis=0：写成 0 得到的是 (3,16)，矩阵乘的形状对不上，会报 mat1 and mat2 shapes cannot be multiplied。
  3. W 必须是 (3,1) 而不是 (3,)：torch.randn(3, requires_grad=True) 得到的是一维张量，与 X(16,3) 做 matmul 结果会是 (16,)，与 Y(16,1) 相减时广播成 (16,16)，Loss 数会大得离谱却不报错——这是最隐蔽的坑。
  4. 数据要转成 float：torch.from_numpy(X) 会保留 numpy 的 float64，而 torch.randn 产出的是 float32，两者混算虽然能跑，但会触发类型提升与潜在警告；课件统一加了 .float()。
  5. 增广列必须放在最前面且与 W 的第 0 个分量对应：如果 X 的列序与 W 的物理含义对不上，模型照样能收敛，但「哪个权重是偏置」就说不清了。
  6. mean 与 sum 的关系：0.5*torch.mean(e²) 与 (1/(2n))*torch.sum(e²) 等价；换成 sum 而不缩小，会等价于把学习率放大了 n 倍，同样容易发散。

  1. os.environ['KMP_DUPLICATE_LIB_OK']='True' 只是”止痛药”：它的作用是让 libiomp5md.dll 重复加载时不再直接崩溃，并不解决根因（同进程里混入了两份 OpenMP）；能修环境就别长期靠它。
  2. train_x[:, 5] 的下标要从 0 数：RM 是第 6 个属性，所以索引是 5；写成 6 会取到 DIS，模型照跑但结果是错的。
  3. 维度要对齐：w*x_train + b 中 x_train 是 (n,1)、w 是 (1,)，广播后得到 (n,1)，与 y_train(n,1) 相减没问题；如果 w 写成标量而 y_train 是 (n,)，Loss 会因为广播变成 (n,n) 的怪结果。

  5. ** .data.zero_() 里的下划线**：PyTorch 里所有以 _ 结尾的方法（zero_、add_、requires_grad_）都是原地修改，没有返回新张量；写成 w.grad.zero() 会报 AttributeError。
  6. 变量名 iter 覆盖内置函数：课件把迭代次数命名为 iter，这会遮住 Python 内置的 iter()；学习时无碍，工程里建议改成 num_iter/max_iter。
  7. ** matplotlib 中文与负号**：不设 plt.rcParams['font.sans-serif']=['SimHei']，中文会变方块；不设 axes.unicode_minus=False，负号会变方块。
  8. dtype 混用：数据处理用 float64，而 torch.randn 产出 float32；课件的做法是在取 RM 列时用 .float() 统一成 float32，与参数一致。

结论：把 13 个属性都用上之后，训练 Loss 从 27.6 降到 16.4（约降 40%），测试 Loss 从 26.3 降到 17.8 —— 多特征确实显著提升了拟合能力；同时测试 Loss 始终略高于训练 Loss，说明有轻微过拟合但不严重。这正好解释了为什么”一元线性回归做波士顿房价预测”在 10.6.1 里只够用来演示流程，而真正做预测要用 10.6.2 / 10.7.5 的多元模型。

10.7.5.6 易错点

  1. torch.cat 的 dim 必须写对：torch.cat([x0_train, x_train], dim=0) 会变成 (2n, 13) 而不是 (n, 14)，接着 matmul 直接报形状错误；dim=1 才是”按列拼”。
  2. 全 1 列必须与 W 的分量个数匹配：13 个属性 → 属性矩阵 14 列 → W 必须是 (14,1)。写成 (13,1) 会报 mat1 and mat2 shapes cannot be multiplied。
  3. 归一化的方向：课件把特征和标签都做了 min-max 归一化（y_train 也归一化），因此打印出来的 Loss（16.4 这种量级）是归一化后的数值，不能与 10.6.2 里未归一化的 Loss（几到几十）直接比大小。
  4. 在张量上别用 pandas 的 axis=0：x.min(axis=0) 在 2 维张量上返回命名元组，直接参与算术会报 TypeError；张量上要么写 x.min(dim=0)[0]，要么把归一化放到转张量之前用 pandas 做。
  5. torch.tensor(已有张量)会告警：课件写成 torch.tensor(torch.cat([...]))，运行时会提示”这里发生了拷贝”；直接 torch.cat 返回的就是张量，不必再包一层。
  6. 梯度清零的位置：和 10.7.4 一样，清零在 backward() 之前，第一轮 W.grad 是 None，必须加 if W.grad is not None: 守卫。
  7. W.data = W.data - ... 之后别忘了 W.grad 还在：因为是在下一次循环开头清零，所以更新的那一轮 W.grad 一直是可用的，顺序不能颠倒成”先更新后求导”。
  8. np.random.randn 没有固定种子：本节参数初值是随机的，每次运行结果会有细微差别；若要与课件输出完全一致，需要自己补 np.random.seed(612)（课件在 10.7.4/10.7.5 里确实出现过 np.random.seed(612) 的调用片段，但抽取顺序显示它属于 10.7.4 的参数初值段）。
