11.7.1.3 核心 API 说明

API 作用 用法要点
torch.tensor(data, requires_grad=True) 把 numpy 值包成可求导的张量 只有浮点张量能设 requires_grad=True；np.random.randn() 是 float64，故 w、b 都是 float64
torch.exp(x) 逐元素指数 sigmoid 写作 1/(1+torch.exp(-(w*x+b)))
torch.log(x) 逐元素自然对数 交叉熵里用；注意不能对 0 取对数（预测概率为 0 会得 -inf）
torch.mean(x) 求全部元素的平均 对应 tf.reduce_mean
torch.where(cond, a, b) 条件选择 torch.where(pred<0.5, 0, 1)：概率小于 0.5 判 0 类，否则判 1 类
torch.eq(a,b) 逐元素比较，返回 bool 张量 对应 tf.equal
torch.tensor(bool_tensor, dtype=torch.float32) 布尔转浮点 对应 tf.cast；课件就是这么写的（会有一条 UserWarning，不影响结果）
torch.autograd.grad(outputs, inputs) 返回梯度（列表） 与 backward() 不同：有返回值、不写 .grad
手写更新 w - learn_rate*dL_dw 再包 torch.tensor(..., requires_grad=True) 更新参数 因为要「重新变成一个叶子张量」才能继续求导，所以每次更新都要重新包一次

11.7.1.6 易错点

  1. 只有浮点张量能求导：torch.tensor([1,2], requires_grad=True) 直接报错（整型不能求导）。课件用 np.random.randn() 造初值，得到的是 float64，这是能求导的关键。
  2. torch.autograd.grad 与 backward() 二选一，别混：grad 返回梯度列表、不写 .grad；backward() 不返回、把梯度累加进 .grad。11.7.1 用的是前者，11.7.2 第一部分用的是后者，11.7.3 又用回前者——同一讲里两种写法都出现了。
  3. 每次更新参数都要重新包一层 torch.tensor(..., requires_grad=True)：因为 w - learn_rate*dL_dw 的结果是非叶子节点；不重新包，下一轮的 torch.autograd.grad(Loss, w) 会因 w 不在计算图中而报错。这也是课件「最后运用自减操作实现对参数更新」那句话背后的原因。
  4. 准确率里的 torch.tensor(x, dtype=torch.float32) 会给出 UserWarning（推荐 x.float() 或 x.clone().detach()）。课件写法能用，只是会打印一条警告；想干净就写 torch.eq(...).float().mean()。
  5. 打印格式决定输出长相：因为 Loss_train 是 0 维张量，"{}".format(Loss_train) 会调用 PyTorch 的 __format__ 打印数值本身（0.8528074207031997）；若换成 str(Loss_train) 就会变成 tensor(0.8528)。课件用的是 .format()，所以截图里是干净的全精度数值。
  6. 预测时别忘减同一个均值：pred_test = 1/(1+torch.exp(-(w*(x_test-np.mean(x))+b)))，漏掉 x_test-np.mean(x) 会得到完全错误的结果（训练时用的就是中心化后的数据）。
  7. torch.where 的参数顺序：torch.where(条件, 条件成立时的值, 条件不成立时的值)。pred<0.5 成立判 0 类，所以写 torch.where(pred<0.5, 0, 1)，与 11.2 的 tf.where 完全一样。
  8. 课件在绘图单元里第二次调用了 np.random.seed(612)：重复设种子不会改变结果，但会让「代码到底从哪一行开始训练」变得不容易看清——本文只保留一次。

11.7.2.8 易错点

  1. 梯度会累加，用 .grad 就必须每轮重建 W：课件写 W=torch.tensor(W-learn_rate*W.grad, requires_grad=True)，这行同时完成了「读梯度 → 更新 → 变成新的叶子张量」三件事。若写成 W.data -= learn_rate*W.grad（11.7.3 的写法），则必须在下一轮 backward() 前清零 W.grad（W.grad.zero_() 或 W.grad=None），否则梯度越加越大。
  2. torch.matmul(X,W) 要求两个张量类型一致：X 必须是 float32（课件用 torch.tensor(..., dtype=torch.float32) 显式转），否则 matmul 会因 Double 与 Float 不匹配报错。
  3. 增广列 1 的个数要与样本数一致：np.ones(num_train) 而不是 np.ones(num)；第二部分有两套样本，必须分别用 num_train、num_test。
  4. 中心化必须分训练集/测试集各自算均值：课件第一部分对训练集中心化、第二部分对 x_train 与 x_test 分别中心化。注意：这属于课件的简化处理——严格做法是测试集减去训练集的均值；若两者分布接近，结果差别很小，但预测新样本时应沿用训练集的均值。
  5. 决策边界的负号：y_=-(W[1]*x_+W[0])/W[2]。由决策方程 W[0]+W[1]x+W[2]y=0 解出 y=-(W[0]+W[1]x)/W[2]，负号在最外层；漏掉负号会把分类线画成「垂直翻转」的样子，正好与正确结果相反。
  6. 图例与颜色说明是两回事：散点用 cmap=cm_pt（自定义 ListedColormap(['blue','red'])）区分两类；曲线颜色（蓝=训练集、红=测试集）是在 plt.plot(..., color=...) 里指定的，两者的 blue/red 含义不同，别混。
  7. torch.tensor(W) 这一行：抽取中它出现在参数初值后与每轮更新后（第一部分），作用存疑（见附录 B）。它在课件里能跑通，但如果读者在自己的环境里遇到「element 0 of tensors does not require grad」一类的报错，直接删掉这一行即可；第二部分并没有这一行，照样跑出了图6/图7。
  8. 测试集准确率不再上升不是 bug：图6 的测试集准确率停在 86%，是数据量与模型容量决定的，不要靠继续加迭代次数去「刷」测试集——那只会让训练集继续过拟合。

11.7.3.6 易错点

  1. torch.nn.functional.one_hot 要求整型输入：y_train 是从 CSV 读来的整型标签才能直接喂进去；若标签已被转成 float（例如 dtype=torch.float32），必须写成 .long()，否则报 RuntimeError（one_hot is only applicable to index tensor）。

  2. softmax 一定要给 dim：torch.nn.functional.softmax(z, dim=1) 是「对每个样本的 3 个类别归一化」；漏写 dim 在高维输入下会给出弃用警告，且可能沿错误维度归一化。

  3. 多分类交叉熵的「逐元素相乘再求和」：-torch.sum(Y_train*torch.log(PRED_train))/num_train。Y_train 是独热（每行一个 1），所以乘法自动挑出正确类别那一项；千万别写成 torch.log(Y_train*PRED_train)（那是先乘再取对数，含义完全不同）。

  4. 网格点属性矩阵的拼法（本小节最需要注意的一处）：课件抽取到的写法是

  5. W=W.t() 这一行：抽取中在计算网格预测值之前有一行 W=W.·()（点 + 1 个小写字母 + 括号），按字符数最可能是 W=W.t()。但它会把权重矩阵转置，使分类图所用的判别面与训练得到的 W 不一致，进一步加剧图 6 的异常。本笔记在代码里把它注释掉并标注；若读者在课件 PDF 里能看到这一行，请以课件为准。
